      [recall] What was done in session `2d3c0c63-...`?

  Note the probes themselves are poor: all four are `recall`, none exercise
  the artifact, continuation or decision types, and they ask about session
  identifiers rather than about the work. That is the 3B judge, not the
  harness — but it is the reason a retention number from this judge would
  not be worth publishing even once the run completes.

WHAT WAS PROVEN
  A real defect, found by running the thing rather than reading it.
  parse_probes split on '|' and read field zero as the probe type. Models
  wrap the requested format in a numbered list and pad it with pipes, so a
  real line from qwen2.5:3b looked like:

      1. |What was the command executed at step 27?|ran command 27|

  Field zero was '1. ', which matched no ProbeType, so the line was skipped.
  Every line was skipped. generate_probes returned an empty vector, and an
  empty vector is not an error, so the caller measured nothing and could not
  tell that apart from a context with nothing worth asking.

  Fixed on both sides, with regression tests built from the exact model
  output: the parser strips list markers and surrounding pipes, and the
  generation prompt carries a worked example and forbids numbering, because
  the same model also dropped the TYPE field when given only an abstract
  format. 113 tests pass.

  Also fixed: the mock summarizer branched on the literal word "generate" in
  the prompt, so rewording the prompt mis-routed it to the grading response
  and failed a test for a reason unrelated to its subject.

WHAT IS STILL MISSING
  A retention percentage. The judge is the constraint, not the harness:
  this machine has no Anthropic credentials, and ollama qwen2.5:3b needs
  about 46 seconds per call at 1,541 prompt tokens. One session is nine
  calls across the compressed and control conditions.

  To finish, substitute a Claude-backed Summarizer for RawOllama in
  src/bin/probe_run.rs and run:
      distil-probe <session.jsonl> --probes 6 --model <model>
